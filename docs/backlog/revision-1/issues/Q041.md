# Q041 — Implement autonomous graph revision and provenance

## Outcome

Analysis may propose versioned task-graph revisions that deterministic validation accepts or rejects with complete requirement and provenance tracking.

## Specification anchors

- §13.6 Autonomous graph revision
- §20.7 Hidden dependency discovery
- §4.10 Every decision has provenance

## Dependency

Requires Q040 to be merged and independently confirmed on remote `main`.

## Tier

`T2-capability`

## Constraints

- Models propose; deterministic code validates and commits.
- Committed/merged task history is immutable.
- Preserve Product Specification v0.2 commitments and acceptance criteria.
- Keep Windmill, predecessor automation tooling, and TAKT out of Heniek runtime dependencies.
- Use strict ESM TypeScript, provider-neutral public contracts, and repository conventions.

## Exclusions

- No silent deletion of source requirements.
- No direct model mutation of canonical graph state.
- No factory runtime state, credentials, transcripts, or control artifacts in this repository.
- No unrelated backlog work or speculative scope reduction.

## Acceptance criteria

- [ ] Revisions can add, split, merge, reorder, or supersede unstarted tasks within policy.
- [ ] Every change records rationale, evidence, requirement mapping, affected waves, and validator decision.
- [ ] Invalid, stale, or commitment-narrowing revisions are rejected without partial mutation.
- [ ] Public contracts and generated schemas remain compatible or are versioned deliberately.
- [ ] `pnpm check` passes from a clean checkout on Node.js 24.
- [ ] The pull request is non-draft, self-contained, and uses `Closes <this issue>`.

## Required tests

- Graph-revision operation and stale-version property tests.
- Requirement-loss, cycle, started-task, and policy-violation fixtures.
- Regression tests for every defect discovered while implementing this issue.

## Required evidence

- Before/after graph revision artifact.
- Provenance and validation decision log.
- Exact commands and results for local checks.
- GitHub required-check and merge confirmation.

## Autonomous stop conditions

Stop with a typed blocker and evidence if the predecessor is not merged, queue
markers disagree, a product commitment would need to be narrowed, a required
subscription route cannot be proven, credentials could be exposed, or a genuine
technical ambiguity remains after the issue's bounded spike/ADR path.
