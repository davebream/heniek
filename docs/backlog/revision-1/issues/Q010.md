# Q010 — Implement Codebase detection, registration and instruction-conflict reporting

## Outcome

Heniek detects one or more repositories, registers a logical Codebase, discovers native agent instructions, and reports material precedence conflicts before execution.

## Specification anchors

- §11 Codebases and repositories
- §4.5 Whole-Codebase reasoning
- §8.2 Configuration layers

## Dependency

Requires Q009 to be merged and independently confirmed on remote `main`.

## Tier

`T1-foundation`

## Constraints

- Treat source-issue repository as provenance, not authority.
- Preserve instruction sources and hashes for every run.
- Preserve Product Specification v0.2 commitments and acceptance criteria.
- Keep Windmill, predecessor automation tooling, and TAKT out of Heniek runtime dependencies.
- Use strict ESM TypeScript, provider-neutral public contracts, and repository conventions.

## Exclusions

- No composite workspace provisioning.
- No automatic semantic resolution of material instruction conflicts.
- No factory runtime state, credentials, transcripts, or control artifacts in this repository.
- No unrelated backlog work or speculative scope reduction.

## Acceptance criteria

- [ ] Single-root and multi-root detection produce stable Codebase and repository IDs.
- [ ] Registration records remotes, default branches, paths, and instruction provenance.
- [ ] Conflict diagnostics distinguish additive guidance from incompatible requirements.
- [ ] Public contracts and generated schemas remain compatible or are versioned deliberately.
- [ ] `pnpm check` passes from a clean checkout on Node.js 24.
- [ ] The pull request is non-draft, self-contained, and uses `Closes <this issue>`.

## Required tests

- Repository topology and remote normalization fixtures.
- Instruction precedence and conflict-classifier tests.
- Regression tests for every defect discovered while implementing this issue.

## Required evidence

- Registered-Codebase snapshot.
- Conflict report fixture with source anchors.
- Exact commands and results for local checks.
- GitHub required-check and merge confirmation.

## Autonomous stop conditions

Stop with a typed blocker and evidence if the predecessor is not merged, queue
markers disagree, a product commitment would need to be narrowed, a required
subscription route cannot be proven, credentials could be exposed, or a genuine
technical ambiguity remains after the issue's bounded spike/ADR path.
