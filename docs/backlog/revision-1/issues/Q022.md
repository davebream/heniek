# Q022 — Implement subscription billing guard, env scrubbing, redaction and process cleanup

## Outcome

A fail-closed guard verifies subscription routes, constructs a minimal environment, redacts sensitive data, and cleans complete process trees for every execution.

## Specification anchors

- §10.4 Billing guard
- §27 Security and privacy
- §23.5 Required compatibility tests

## Dependency

Requires Q021 to be merged and independently confirmed on remote `main`.

## Tier

`T2-capability`

## Constraints

- API-key variables are denied by default for subscription profiles.
- Secrets are never written to artifacts, exports, or diagnostics.
- Preserve Product Specification v0.2 commitments and acceptance criteria.
- Keep Windmill, predecessor automation tooling, and TAKT out of Heniek runtime dependencies.
- Use strict ESM TypeScript, provider-neutral public contracts, and repository conventions.

## Exclusions

- No metered fallback.
- No broad inheritance of host environment or credential directories.
- No factory runtime state, credentials, transcripts, or control artifacts in this repository.
- No unrelated backlog work or speculative scope reduction.

## Acceptance criteria

- [ ] Claude, Codex, and Cursor subscription profiles report a verified billing route before work.
- [ ] Known key names, token shapes, URLs, headers, and provider payloads are redacted.
- [ ] Success, failure, cancellation, timeout, and daemon crash leave no orphan credential-bearing process.
- [ ] Public contracts and generated schemas remain compatible or are versioned deliberately.
- [ ] `pnpm check` passes from a clean checkout on Node.js 24.
- [ ] The pull request is non-draft, self-contained, and uses `Closes <this issue>`.

## Required tests

- Hostile-env and redaction corpus tests.
- Process-tree fault injection and credential-revocation tests.
- Regression tests for every defect discovered while implementing this issue.

## Required evidence

- Billing guard attestation.
- Redaction and orphan-process scan report.
- Exact commands and results for local checks.
- GitHub required-check and merge confirmation.
