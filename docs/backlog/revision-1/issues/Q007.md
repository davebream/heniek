# Q007 — Implement immutable artifacts and transactional stage completion

## Outcome

Immutable, content-addressed artifacts are durably written and validated before a stage completion transaction can release dependent work.

## Specification anchors

- §4.4 Artifact before completion state
- §16.2 Hybrid mutability
- §16.6 Transactional stage completion

## Dependency

Requires Q006 to be merged and independently confirmed on remote `main`.

## Tier

`T1-foundation`

## Constraints

- Use atomic file publication plus SQLite metadata transaction.
- Preserve media type, schema version, producer, and source lineage.
- Preserve Product Specification v0.2 commitments and acceptance criteria.
- Keep Windmill, Kombajn, and TAKT out of Heniek runtime dependencies.
- Use strict ESM TypeScript, provider-neutral public contracts, and repository conventions.

## Exclusions

- No artifact interpretation by downstream models.
- No remote artifact store.
- No factory runtime state, credentials, transcripts, or control artifacts in this repository.
- No unrelated backlog work or speculative scope reduction.

## Acceptance criteria

- [ ] A successful stage cannot reference a missing, partial, or schema-invalid artifact.
- [ ] Retries create new immutable attempts without mutating earlier artifacts.
- [ ] Crash recovery removes or classifies orphan temporary files without losing committed data.
- [ ] Public contracts and generated schemas remain compatible or are versioned deliberately.
- [ ] `pnpm check` passes from a clean checkout on Node.js 24.
- [ ] The pull request is non-draft, self-contained, and uses `Closes <this issue>`.

## Required tests

- Fault injection before and after each durability boundary.
- Content hash, immutability, and concurrent-reader tests.
- Regression tests for every defect discovered while implementing this issue.

## Required evidence

- Transactional sequence test trace.
- Artifact inventory with verified hashes.
- Exact commands and results for local checks.
- GitHub required-check and merge confirmation.

## Autonomous stop conditions

Stop with a typed blocker and evidence if the predecessor is not merged, queue
markers disagree, a product commitment would need to be narrowed, a required
subscription route cannot be proven, credentials could be exposed, or a genuine
technical ambiguity remains after the issue's bounded spike/ADR path.
