# Q040 — Implement task DAG validation, wave eligibility and capacity gates

## Outcome

A validated whole-task DAG computes deterministic waves subject to dependencies, workspace conflicts, account capacity, and configured concurrency.

## Specification anchors

- §20.2 Task-level DAG
- §20.4 Wave eligibility
- §24 Limits, retries, and safeguards

## Dependency

Requires Q039 to be merged and independently confirmed on remote `main`.

## Tier

`T1-foundation`

## Constraints

- Tasks, not internal stages, are epic scheduling nodes.
- Eligibility is a pure decision over versioned state.
- Preserve Product Specification v0.2 commitments and acceptance criteria.
- Keep Windmill, Kombajn, and TAKT out of Heniek runtime dependencies.
- Use strict ESM TypeScript, provider-neutral public contracts, and repository conventions.

## Exclusions

- No task execution.
- No stage-level epic interleaving.
- No factory runtime state, credentials, transcripts, or control artifacts in this repository.
- No unrelated backlog work or speculative scope reduction.

## Acceptance criteria

- [ ] Validation rejects cycles, missing nodes, impossible write conflicts, and invalid terminal dependencies.
- [ ] Wave computation respects dependencies, writer leases, profile/account capacity, and run limits.
- [ ] Every deferred task has an explicit blocking reason.
- [ ] Public contracts and generated schemas remain compatible or are versioned deliberately.
- [ ] `pnpm check` passes from a clean checkout on Node.js 24.
- [ ] The pull request is non-draft, self-contained, and uses `Closes <this issue>`.

## Required tests

- DAG/cycle and topological-order property tests.
- Capacity, write-conflict, failure, and cancellation wave fixtures.
- Regression tests for every defect discovered while implementing this issue.

## Required evidence

- Versioned DAG and wave plan.
- Eligibility decision trace.
- Exact commands and results for local checks.
- GitHub required-check and merge confirmation.
