# Q024 — Implement YAML pipeline schema, parser and diagnostics

## Outcome

Versioned YAML pipeline definitions parse into provider-neutral graph contracts with source-located diagnostics and deterministic normalized output.

## Specification anchors

- §8 Configuration model
- §14.1 Arbitrary declarative graph
- §14.3 Illustrative stage definition

## Dependency

Requires Q023 to be merged and independently confirmed on remote `main`.

## Tier

`T1-foundation`

## Constraints

- Accept only the documented restricted YAML subset.
- Require fixed v1 stage types and explicit schema version.
- Preserve Product Specification v0.2 commitments and acceptance criteria.
- Keep Windmill, Kombajn, and TAKT out of Heniek runtime dependencies.
- Use strict ESM TypeScript, provider-neutral public contracts, and repository conventions.

## Exclusions

- No scheduler or stage execution.
- No runtime plugin API for new stage types.
- No factory runtime state, credentials, transcripts, or control artifacts in this repository.
- No unrelated backlog work or speculative scope reduction.

## Acceptance criteria

- [ ] Parser validates nodes, edges, profiles, conditions, policies, limits, modes, and outputs.
- [ ] Diagnostics identify file, path, line/column, violated rule, and suggested correction.
- [ ] Equivalent YAML normalizes to byte-identical graph JSON.
- [ ] Public contracts and generated schemas remain compatible or are versioned deliberately.
- [ ] `pnpm check` passes from a clean checkout on Node.js 24.
- [ ] The pull request is non-draft, self-contained, and uses `Closes <this issue>`.

## Required tests

- Golden valid/invalid pipeline corpus.
- Parser fuzzing and canonicalization property tests.
- Regression tests for every defect discovered while implementing this issue.

## Required evidence

- Generated pipeline JSON Schema.
- Diagnostic corpus snapshot.
- Exact commands and results for local checks.
- GitHub required-check and merge confirmation.
