# Q001 — Establish Heniek domain IDs, state vocabulary and versioned JSON contracts

## Outcome

A provider-neutral contracts package defines branded domain IDs, canonical state vocabularies, and versioned JSON contracts for execution backends, task sources, forge backends, runs, interactions, and artifacts.

## Specification anchors

- §5 Core domain terminology
- §16 Canonical run state and artifacts
- §22 ExecutionBackend abstraction

## Dependency

First queue item. Requires only the approved revision-1 bootstrap.

## Tier

`T1-foundation`

## Constraints

- Use TypeBox and Ajv with stable schema identifiers and explicit version fields.
- Keep provider DTOs and transport details outside domain contracts.
- Preserve Product Specification v0.2 commitments and acceptance criteria.
- Keep Windmill, Kombajn, and TAKT out of Heniek runtime dependencies.
- Use strict ESM TypeScript, provider-neutral public contracts, and repository conventions.

## Exclusions

- No database implementation, daemon transport, or provider adapter.
- No unversioned public payload.
- No factory runtime state, credentials, transcripts, or control artifacts in this repository.
- No unrelated backlog work or speculative scope reduction.

## Acceptance criteria

- [ ] All public contract families compile to TypeScript and deterministic checked-in JSON Schema.
- [ ] Every state transition vocabulary has documented terminal and non-terminal values.
- [ ] Compatibility tests reject unknown versions and provider-specific field leakage.
- [ ] Public contracts and generated schemas remain compatible or are versioned deliberately.
- [ ] `pnpm check` passes from a clean checkout on Node.js 24.
- [ ] The pull request is non-draft, self-contained, and uses `Closes <this issue>`.

## Required tests

- Schema round-trip and invalid-payload table tests.
- Property tests for ID namespaces and state-enum exhaustiveness.
- Regression tests for every defect discovered while implementing this issue.

## Required evidence

- Generated-schema manifest and hashes.
- Contract compatibility test output.
- Exact commands and results for local checks.
- GitHub required-check and merge confirmation.
