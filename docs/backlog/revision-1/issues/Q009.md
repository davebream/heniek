# Q009 — Implement Unix-socket JSON-RPC and minimal CLI handshake/status

## Outcome

An authenticated JSON-RPC 2.0 server over the daemon Unix socket and a minimal `heniek` CLI provide version negotiation, health, status, and machine-readable errors.

## Specification anchors

- §6.2 Client surfaces
- §6.3 Local transports and authentication
- §22 ExecutionBackend abstraction

## Dependency

Requires Q008 to be merged and independently confirmed on remote `main`.

## Tier

`T1-foundation`

## Constraints

- Frame requests unambiguously and cap payload size.
- Version protocol methods independently from domain contracts.
- Preserve Product Specification v0.2 commitments and acceptance criteria.
- Keep Windmill, Kombajn, and TAKT out of Heniek runtime dependencies.
- Use strict ESM TypeScript, provider-neutral public contracts, and repository conventions.

## Exclusions

- No TUI, MCP facade, or full operational command set.
- No TCP fallback.
- No factory runtime state, credentials, transcripts, or control artifacts in this repository.
- No unrelated backlog work or speculative scope reduction.

## Acceptance criteria

- [ ] CLI discovers the resolved socket and performs authenticated protocol negotiation.
- [ ] Malformed, oversized, unauthorized, unknown, and cancelled requests return stable JSON-RPC errors.
- [ ] Human and JSON output modes expose daemon, schema, and compatibility status.
- [ ] Public contracts and generated schemas remain compatible or are versioned deliberately.
- [ ] `pnpm check` passes from a clean checkout on Node.js 24.
- [ ] The pull request is non-draft, self-contained, and uses `Closes <this issue>`.

## Required tests

- Protocol framing and error-code table tests.
- Real socket concurrent-client and disconnect integration tests.
- Regression tests for every defect discovered while implementing this issue.

## Required evidence

- JSON-RPC compatibility fixture.
- CLI handshake transcript with secrets redacted.
- Exact commands and results for local checks.
- GitHub required-check and merge confirmation.

markers disagree, a product commitment would need to be narrowed, a required
subscription route cannot be proven, credentials could be exposed, or a genuine
technical ambiguity remains after the issue's bounded spike/ADR path.
