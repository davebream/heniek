# Q014 — Implement accounts, workers, roles, profiles and effort resolution

## Outcome

Named accounts, workers, roles, and profiles resolve deterministically into an auditable execution request with validated effort and override policy.

## Specification anchors

- §9 Accounts, workers, roles, and profiles
- §8 Configuration model
- §10.1 v1 engines

## Dependency

Requires Q013 to be merged and independently confirmed on remote `main`.

## Tier

`T2-capability`

## Constraints

- Accounts select explicit credential identities.
- Invocation overrides are allowlisted and precedence is visible.
- Preserve Product Specification v0.2 commitments and acceptance criteria.
- Keep Windmill, predecessor automation tooling, and TAKT out of Heniek runtime dependencies.
- Use strict ESM TypeScript, provider-neutral public contracts, and repository conventions.

## Exclusions

- No automatic account pooling or quota rotation.
- No provider-specific fields in public profile contracts.
- No factory runtime state, credentials, transcripts, or control artifacts in this repository.
- No unrelated backlog work or speculative scope reduction.

## Acceptance criteria

- [ ] Layered configuration resolves worker, role, engine, account, model, effort, and execution mode.
- [ ] Invalid engine/model/effort combinations fail before workspace mutation.
- [ ] Resolved profiles retain source provenance and a stable redacted fingerprint.
- [ ] Public contracts and generated schemas remain compatible or are versioned deliberately.
- [ ] `pnpm check` passes from a clean checkout on Node.js 24.
- [ ] The pull request is non-draft, self-contained, and uses `Closes <this issue>`.

## Required tests

- Configuration precedence and override matrix.
- Cross-engine capability/effort validation table tests.
- Regression tests for every defect discovered while implementing this issue.

## Required evidence

- Resolved-profile snapshots.
- Invalid-combination diagnostics.
- Exact commands and results for local checks.
- GitHub required-check and merge confirmation.

## Autonomous stop conditions

markers disagree, a product commitment would need to be narrowed, a required
subscription route cannot be proven, credentials could be exposed, or a genuine
technical ambiguity remains after the issue's bounded spike/ADR path.
