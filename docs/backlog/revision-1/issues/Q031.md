# Q031 — Ship the careful pipeline using the accepted Kombajn review semantics

## Outcome

A bundled `careful` pipeline preserves accepted Kombajn critic, reviewer, verifier, evidence, and repair invariants through Heniek-native contracts.

## Specification anchors

- §19 Review and verification
- §30.2 `careful`
- §32 Development-time reference extraction charter

## Dependency

Requires Q030 to be merged and independently confirmed on remote `main`.

## Tier

`T2-capability`

## Constraints

- Document each extracted invariant and rejected complexity.
- Review uses fresh posture/context and structured findings plus Markdown.
- Preserve Product Specification v0.2 commitments and acceptance criteria.
- Keep Windmill, Kombajn, and TAKT out of Heniek runtime dependencies.
- Use strict ESM TypeScript, provider-neutral public contracts, and repository conventions.

## Exclusions

- No Kombajn runtime dependency or giant role roster.
- No mandatory cross-provider diversity.
- No factory runtime state, credentials, transcripts, or control artifacts in this repository.
- No unrelated backlog work or speculative scope reduction.

## Acceptance criteria

- [ ] Design critique, plan validation, implementation, code review, repair, and final verification have explicit artifacts.
- [ ] Findings carry severity, evidence, disposition, and verification state.
- [ ] A full fake run proves accepted/rejected findings and bounded repair.
- [ ] Public contracts and generated schemas remain compatible or are versioned deliberately.
- [ ] `pnpm check` passes from a clean checkout on Node.js 24.
- [ ] The pull request is non-draft, self-contained, and uses `Closes <this issue>`.

## Required tests

- Pipeline conformance and finding-schema tests.
- Careful end-to-end scenario with seeded critic/reviewer failures.
- Regression tests for every defect discovered while implementing this issue.

## Required evidence

- Extraction record mapping invariants to contracts.
- Run export showing findings and repairs.
- Exact commands and results for local checks.
- GitHub required-check and merge confirmation.

## Autonomous stop conditions

Stop with a typed blocker and evidence if the predecessor is not merged, queue
markers disagree, a product commitment would need to be narrowed, a required
subscription route cannot be proven, credentials could be exposed, or a genuine
technical ambiguity remains after the issue's bounded spike/ADR path.
