# Q044 — Spike F and implement partial multi-repository reconciliation

## Outcome

A spike defines failure-safe prepare/verify/publish reconciliation when a multi-repository operation partially succeeds, followed by deterministic implementation.

## Specification anchors

- §21.2 Multi-repository epic
- §21.7 Cross-repository delivery
- §34 Multi-repository integration cannot be atomic

## Dependency

Requires Q043 to be merged and independently confirmed on remote `main`.

## Tier

`T0-evidence`

## Constraints

- Never claim cross-repository atomicity.
- Use observed external state and expected SHAs, not remembered intent alone.
- Preserve Product Specification v0.2 commitments and acceptance criteria.
- Keep Windmill, Kombajn, and TAKT out of Heniek runtime dependencies.
- Use strict ESM TypeScript, provider-neutral public contracts, and repository conventions.

## Exclusions

- No destructive rollback of externally consumed commits.
- No automatic choice under genuine semantic ambiguity.
- No factory runtime state, credentials, transcripts, or control artifacts in this repository.
- No unrelated backlog work or speculative scope reduction.

## Acceptance criteria

- [ ] ADR enumerates partial integration/publication states and safe forward/compensating actions.
- [ ] Reconciler reaches a truthful terminal or typed-blocked state after restart.
- [ ] Repeated reconciliation is idempotent and records every external observation.
- [ ] Public contracts and generated schemas remain compatible or are versioned deliberately.
- [ ] `pnpm check` passes from a clean checkout on Node.js 24.
- [ ] The pull request is non-draft, self-contained, and uses `Closes <this issue>`.

## Required tests

- Failure injection after each repository operation.
- External mutation, retry, restart, and irreconcilable-state scenarios.
- Regression tests for every defect discovered while implementing this issue.

## Required evidence

- Partial-state ADR and state table.
- Reconciliation traces for every failure point.
- Exact commands and results for local checks.
- GitHub required-check and merge confirmation.

## Autonomous stop conditions

Stop with a typed blocker and evidence if the predecessor is not merged, queue
markers disagree, a product commitment would need to be narrowed, a required
subscription route cannot be proven, credentials could be exposed, or a genuine
technical ambiguity remains after the issue's bounded spike/ADR path.
